# Plan: Fix Login and Clean Up Code

## Issues Found

### 1. Security Vulnerability - Hardcoded Credentials
**Location:** `src/js/admin.js:2-7`

The USERS array contains hardcoded usernames and passwords in plain text:
```js
const USERS = [
  { username: 'superadmin', password: 'SuperAdmin@10900', role: 'Superadmin' },
  ...
];
```

This is a security risk. Passwords should not be stored in client-side code.

### 2. Missing Username Input Field
**Location:** `admin.html:18-26`

The login form only has:
- Role select dropdown
- Password input

But no username input field. Users cannot enter their own username/password.

### 3. Code Organization
**Location:** `src/js/admin.js:1-2399`

The JavaScript file is 2399 lines with:
- Inline styles mixed throughout
- Functions not well organized by section
- No clear separation of concerns

## Proposed Changes

### Phase 1: Fix Login Form (admin.html)
1. Add username input field to the login form
2. Update placeholder text to be clearer
3. Keep role selection but make username required

### Phase 2: Server-Side Authentication (admin.js)
1. Remove hardcoded USERS array
2. Replace with credential validation via Apps Script backend (`doLogin` will send username/password to server)
3. Store valid users list on backend (passwords won't be in client code)
4. Add proper error handling for login failures

### Phase 3: Code Cleanup (admin.js)
1. Extract inline styles to CSS variables/classes
2. Reorganize code into clearly marked sections:
   - CONFIG/SETTINGS
   - STATE MANAGEMENT  
   - AUTHENTICATION (with server-side validation)
   - DATA LOADING
   - RENDERING
   - UTILITIES
3. Add clear section dividers with comments

## Implementation Steps

1. Edit `admin.html` - Add username input field
2. Edit `src/js/admin.js`:
   - Remove hardcoded USERS constant
   - Add `doLogin()` will POST credentials to backend for validation
   - Backend returns user role on successful authentication
   - Organize code into logical sections with clear comments

## Security Implementation
- Passwords will NOT be stored in client-side JavaScript
- Login form submits to Apps Script endpoint for server-side validation
- Backend maintains user database and returns only the authenticated user's role
- Session managed via JavaScript state (currentUser object)
