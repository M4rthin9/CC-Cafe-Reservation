# แผนแก้ไข Flow การจอง: จอง → ตรวจสอบผู้เข้าร่วม → ตรวจสอบวินัย → ชำระเงิน

## เป้าหมาย (Goal)
ทำให้ flow การจองเป็นลำดับ: **จอง → ตรวจสอบผู้เข้าร่วม → ตรวจสอบวินัย → ชำระเงิน → (ชำระแล้ว → เสร็จสิ้น)**

## สรุปผลการตรวจสอบโค้ด (สำคัญมาก)
Logic หลักของ flow นี้ **ถูก implement ไว้แล้วเกือบทั้งหมด**:
- ตอนจอง สถานะเริ่มต้น = `รอตรวจสอบผู้เข้าร่วม` (`src/js/booking.js:920`)
- Backend state machine ถูกต้องแล้ว (`google_apps_script_updated.js:441-449`):
  - `รอตรวจสอบผู้เข้าร่วม` → `รอตรวจสอบวินัย` → `รอชำระเงิน` → `ชำระแล้ว` → `เสร็จสิ้น`
- Admin UI (`src/js/admin.js`) มี action `approve_participant` (Tadtel) → `รอตรวจสอบวินัย` และ `approve_discipline` (Vinai) → `รอชำระเงิน` ครบถ้วน
- หน้า status (`src/js/status.js`) แสดงสถานะ `รอตรวจสอบผู้เข้าร่วม` ได้แล้ว

**คงเหลือ 2 กลุ่มปัญหาที่ยังไม่ตรงกับ flow ใหม่:**
1. **Bug logic (backend):** สิทธิ์ role `Finance` ไม่อนุญาตให้ตั้งสถานะ `ชำระแล้ว` ทำให้ Finance ยืนยันการชำระเงินไม่ได้
2. **ข้อความ/ป้ายกำกับ (public-facing)** หลายจุดยังบอกว่าหลังจองไป "ตรวจสอบวินัย" ทันที (flow เก่า)

## งานที่ต้องทำ (Ordered Tasks)

### ส่วนที่ 1 — แก้ Bug Logic (backend) [ลำดับความสำคัญสูงสุด]

1. **แก้สิทธิ์ Finance ให้ยืนยันการชำระเงินได้** — `google_apps_script_updated.js`
   - ที่ `handleUpdateStatus` ตัวแปร `roleAllowedStatuses` (บรรทัด ~451-457)
   - ปัจจุบัน: `'Finance': ['เสร็จสิ้น', 'ไม่อนุมัติ']`
   - แก้เป็น: `'Finance': ['ชำระแล้ว', 'เสร็จสิ้น', 'ไม่อนุมัติ']`
   - เหตุผล: `confirmPayment()` (`src/js/admin.js:1555`) ตั้งสถานะ `รอชำระเงิน → ชำระแล้ว` ผ่าน action `updateStatus` แต่ backend บล็อก Finance ทำให้ยืนยันชำระเงินล้มเหลว
   - **หมายเหตุการ deploy:** ไฟล์นี้เป็น Google Apps Script — หลังแก้ต้อง redeploy ผ่าน `clasp push` / เผยแพร่เวอร์ชันใหม่ จึงจะมีผล

2. **ตรวจสอบความสอดคล้อง `allowedTransitions` (backend)** — ยืนยันว่าไม่ต้องแก้
   - `'รอชำระเงิน': ['ชำระแล้ว', 'ยกเลิก']` และ `'ชำระแล้ว': ['เสร็จสิ้น', 'ยกเลิก']` ถูกต้องแล้ว
   - งานนี้เป็นการ verify เท่านั้น ไม่ต้องเปลี่ยนโค้ด

   - ตรวจทานข้อความคู่มืออื่น (บรรทัด 1174, 1303, 1352, 1936-1937, 2225-2265) ให้ลำดับ Tadtel(ผู้เข้าร่วม) มาก่อน Vinai(วินัย) สอดคล้องกัน

## จุดที่ **ยืนยันว่าถูกต้องแล้ว** (ไม่ต้องแก้)
- `src/js/booking.js:920` สถานะเริ่มต้น `รอตรวจสอบผู้เข้าร่วม` ✓
- Backend `allowedTransitions` และ `validStatuses` ✓
- Backend `roleAllowedStatuses` สำหรับ `Tadtel` (`รอตรวจสอบวินัย`) และ `Vinai` (`รอชำระเงิน`) ✓
- Admin quickStatusAdvance / updateStatus permission checks ✓
- `src/js/status.js` getStatusPill รองรับ `รอตรวจสอบผู้เข้าร่วม` ✓

## ความเสี่ยง (Risks)
- **การ deploy backend:** `google_apps_script_updated.js` ต้อง redeploy (clasp push / เวอร์ชันใหม่) — ถ้าลืม การแก้สิทธิ์ Finance จะไม่มีผลจริง
- **i18n key `step2` ใช้ร่วมหลายที่:** เปลี่ยนข้อความเดียวกระทบหลายหน้า — พิจารณาเพิ่ม key ใหม่แทนการแก้ทับ
- **ข้อมูลเก่าในชีต:** การจองเก่าที่มีสถานะ legacy `รอตรวจสอบ` จะถูก `normalizeStatus` map เป็น `รอตรวจสอบวินัย` (ตามโค้ดปัจจุบัน) — ไม่กระทบ flow ใหม่ แต่ควรรับทราบ
